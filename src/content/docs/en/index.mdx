<p data-model-intro>An LLM computes <strong>next-token probabilities</strong> from its input. Append one choice, then recompute with the longer input.</p>

<Expand id="lesson-model-scope" summary="About this small model">

This illustrative model computes from two inputs and fixed coefficients. It omits position calculations and only references earlier positions and the current one. Real LLMs learn coefficients by reducing prediction errors over many texts.
Tokens are chunks of text: whole words or word parts. The end marker is a stopping token. A high probability does not guarantee factual content.

</Expand>

<Expand id="math-conditional" summary="Which context does this probability describe?">

In P(end \| I went), the text after the bar is the available input; the token before it is a next candidate. A changed input can produce changed probabilities with the same coefficients.

</Expand>

<div data-main-lesson>

Each token’s ID looks up one row in the embedding table. This ordered row of numbers is a <strong>vector</strong>.

<LessonComputation locale="en" stage="tokens" />

<Expand id="math-shape" summary="2 × 4: which number counts tokens?">

The first number, 2, counts the token rows. The second, 4, counts features per token. ID 1 and its four retrieved values are different kinds of numbers.

</Expand>

<Section id="numbers" locale="en">

<div data-main-lesson>

### Transform four input values into two comparison values

To retrieve context, we need numbers for comparing the current position with reference positions. Start with <strong>(0, 1, 0, 1) for went</strong>.
Multiply each input value by a fixed coefficient and add to make one output. Repeating this for output columns is matrix multiplication.

<LessonComputation locale="en" stage="projection" />

<div id="similarity">

### Compare matching entries of the values just produced

The current comparison values are <strong>(0, 2)</strong>. Compare them with <strong>(0, 2) for I</strong> and <strong>(2, 0) for went</strong> by multiplying matching entries and adding.

<LessonComputation locale="en" stage="comparison" />

### Arrange the same dot product as row times column

Keep the comparison unchanged and stand the reference row up as a column. Add reference columns beside it to compare several positions from the same current row.

<LessonComputation locale="en" stage="transpose" />
<LessonComputation locale="en" stage="scores" />

</div>

Pass <strong>the two scores (4, 0)</strong> to the next unit. They are not yet retrieved content or next-vocabulary probabilities.

<Section id="proportion" locale="en">

<div data-main-lesson>

### Turn comparison scores into reference shares

Use <strong>(4, 0)</strong> from the preceding unit to decide how much content to retrieve from each input position. <strong>Softmax</strong> turns scores into shares summing to 1.

<LessonComputation locale="en" stage="shares" />

### Use those shares to gather content from the same input

Retrieve <strong>94.4%</strong> from I and <strong>5.6%</strong> from went. Apply content coefficients to the same input, then multiply and add matching content coordinates using those shares.

<LessonComputation locale="en" stage="aggregation" />

</div>

<Section id="attention" locale="en">
<span id="name-the-roles-we-have-already-used-q--k--v" class="lesson-anchor" aria-hidden="true"></span>

<div data-main-lesson>

<strong>Q</strong> compares from the current position, <strong>K</strong> supplies reference comparison values, and <strong>V</strong> supplies content to retrieve.
Three coefficient tables produce these values from the same input. Use them in the order already followed: compare → reference shares → gather content.

<LessonComputation locale="en" stage="attention" />

Positions within one sequence retrieve content from each other, hence <strong>self-attention</strong>. The output row still belongs to went.
Before joining this head with another one, inspect which input positions it is allowed to read.

</div>

<Section id="positions" locale="en">
<span id="which-positions-can-be-referenced-now" class="lesson-anchor" aria-hidden="true"></span>

<div data-main-lesson>

Predicting a next chunk must not read later information in advance. Each row can therefore reference <strong>itself and preceding positions only</strong>.
This <strong>causal mask</strong> has been applied throughout the calculation.

<LessonComputation locale="en" stage="mask" />

The mask restricts what can be read. Position information is a separate operation that identifies where chunks occur.

<Section id="blocks" locale="en">

<div data-main-lesson>

### Preserve the original input by adding it

Passing attention output alone may lose information from the input. Adding matching input entries provides a <strong>residual connection</strong>.
Then layer normalization adjusts the scale of values within this token.

<LessonComputation locale="en" stage="residual" />

### Transform the normalized values within this token

Attention has already gathered information between tokens. The <strong>FFN</strong> now widens and narrows the values of each token separately.
Its input is exactly the preceding normalization output. ReLU replaces negative entries with zero.

<LessonComputation locale="en" stage="feed-forward" />

### Add and normalize again

Add the row entering the FFN to the row leaving it, then normalize again. This produces <strong>the final representation at went</strong>, ready to score next candidates.

<LessonComputation locale="en" stage="hidden" />

</div>

<Section id="big-picture" locale="en">
<span id="use-the-blocks-final-representation-to-compare-vocabulary-candidates" class="lesson-anchor" aria-hidden="true"></span>

<div data-main-lesson>

Receive the final representation from the preceding unit unchanged. Multiplying by vocabulary coefficients gives scores for <strong>I / went / to school / end</strong>.
Softmax converts those scores into probabilities for the next chunk.

<LessonComputation locale="en" stage="readout" />

<strong>To school has the largest probability, 71.8%.</strong> The input still contains only I / went; to school is a next candidate.
Training compares this prediction with a target. Generation chooses a chunk from these probabilities and appends it.

<Expand id="math-readout" summary="How do input-position shares differ from vocabulary probabilities?">

The two attention shares retrieve content from the two given positions. These four probabilities refer to four next-vocabulary candidates. The vocabulary coefficients turn the final representation into candidate scores.

</Expand>

</div>

<div data-main-lesson>

Comparison values, reference shares, content, final representations and vocabulary probabilities formed one computation. Each appended chunk led to a new prediction.
These probabilities select a next chunk; they do not give the probability that generated content is factual.
