## 1. How to run it

```bash
npm install                        # dependencies (once)
npx playwright install chromium    # for the browser checks (once)

npm run dev            # dev server → http://localhost:4321/llm-visual-lab/
npm run build          # static build → dist/
npm run preview        # serves the build under /llm-visual-lab/

npm test               # complete math suite (vitest)
npm run fixtures       # regenerate the independent references with numpy, Fraction, Decimal
npm run typecheck      # tsc --noEmit
npm run test:e2e       # complete browser suite (desktop and mobile)

# These two need the preview server already running
node scripts/screenshots.mjs docs/screenshots        # screen evidence: pages × theme × width
node scripts/shoot-element.mjs <out.png> <URL> <selector> [click::<selector>] [wait::<ms>]
                                                    # one component, optionally after interacting
```

There is no `lint` or `format check` script. Point 1 of Done in AGENTS.md says to
run only the commands the project provides, so no check is invented in order to
record it as passing. `typecheck` stands in its place.

## 2. What was built

### Documents

Originally 8 pages per language. They were merged into one page in the
single-page rebuild, and that page became the home page; see the last two

### The calculations and the labs

- `src/lib/math/` — pure functions, nothing about the UI. `matrix.ts`,

  picked so every entry of QKᵀ comes out an integer.

  automatically.

Two to begin with, five more added later (see the last section):

## 3. Technical choices, and where they diverge from the plan

| | Version |
| --- | --- |
| Astro | 7.3.2 (static output, built-in i18n) |
| @astrojs/mdx | 8.0.1 |
| @astrojs/markdown-remark | 7.3.x |
| React | 19.3.0 |
| KaTeX | 0.18.7 + remark-math 6 + rehype-katex 7 |
| Vitest | 5.0.0 / Playwright 1.63.0 / TypeScript 5.9.3 |

Where this diverges from section 10 of `docs/plan.md`, and why:

1. **`src/content/docs/{ko,en}/`** — the plan said `src/content/{ko,en}/`. One
   extra level lets a single Astro collection hold both languages and split them
   on the first part of the entry id. The Korean and English versions of a
   document must agree on everything after the language code, and a browser check
   enforces that.
2. **`src/components/lab/`** — the plan's `src/labs/` is unused. Every lab in this
   scope is embedded in the prose; none of them needs a page of its own.
3. **The `markdown.processor` setting** — Astro 7 changed its default markdown
   processor. To use remark and rehype plugins you have to install
   `@astrojs/markdown-remark` separately and pass them through
   `markdown: { processor: unified({...}) }`. Passing them as
   `markdown.remarkPlugins` leaves MDX without them, and the braces inside
   equations get parsed as JSX.
4. **Helpers for `getStaticPaths` have to be imported from a module.** Defined
   inside a page's frontmatter they are invisible when it runs, and it fails with
   `parseId is not defined`. `parseEntryId` lives in `lib/i18n/routing.ts`.

# Design rebuild (2026-09-11)

The scope and the reasons are in `docs/current-task.md`. In short: the content
and the calculations met their goals but the visual work did not, and the causes
were a palette chosen out of habit, default typefaces, and the prose and the labs
being made of the same material.

## What changed

### The tokens were rebuilt in three layers

`src/styles/tokens.css` was rewritten completely: primitives (ramps, palettes,
scales) → semantics (surfaces, ink, lines, data) → component values (cell sizes,
grid rules).

The dark theme became **one line per token** through `light-dark()`. It used to
be 39 declarations copied by hand into a second block, so fixing one side left
the other behind. All three states (OS setting / forced dark / forced light) were
checked in Chromium before this was adopted.

### The colours were measured, not chosen

The validator from the `dataviz` skill was run against the actual surface colours.

| Role | Light | Dark |
| --- | --- | --- |
| Q | `#2a78d6` | `#3987e5` |
| K | `#eb6834` | `#d95926` |
| V | `#1baf7a` | `#199e70` |
| heatmap | the blue sequential ramp `--seq-0…7` | the same ramp, restepped for dark |

All-pairs passes everywhere. Worst CVD separation ΔE 9.2 (light) / 9.4 (dark).

**Where the measurement changed the design** — in light mode K came out at
2.99:1 and V at 2.82:1 against the surface, below 3:1. So Q, K and V are **never
used as text colour.** A colour chip before the name, the row and column
highlight bands, and a 2px underline under the term numbers carry the identity
instead; the text is ink. This matches the dataviz rule, "text never wears the
data color".

### Typefaces

Pretendard variable (dynamic subset) plus JetBrains Mono, both OFL and both
self-hosted. Every serif was removed: a Latin serif heading over Korean
sans-serif body text reads as an accident rather than as a pairing.

### Two materials

- **The reading surface** — neutral near-white, 17px body on 1.75 leading,
  hierarchy made from weight. The current-document mark in the contents changed
  from a filled pill to a rule down the left.
- **The working surface** — a panel colour distinct from the prose. Shadows
  removed, radii reduced from 8px to 5px. Matrices are a joined grid through
  `border-collapse`, not a set of separate boxes. Every number is monospaced.

### Interaction graphics

1. **Connectors** — selecting a result cell draws real SVG curves from that row
   of the left matrix and that column of the right one. `ConnectorOverlay.tsx`
   measures the DOM for the coordinates. The lines pass **behind** the matrices;
   in front they cut across the middle matrix and looked like a drawing error.
   They work in the matrix-product lab and at the projection, scores and
   weighted-sum steps of the attention lab.
2. **The step rail** — seven pills became a rail that shows the pipeline. A line
   runs behind the list and each numbered circle punches through it with its own
   background.
3. **Formula linkage** — only the term for the current step comes forward; the
   rest step back. Q, K and V are distinguished by underline.
4. **Motion and the heatmap** — transitions on the bars and the connectors,
   respecting `prefers-reduced-motion`. The heatmap moved to the validated
   sequential ramp.

## Real bugs fixed along the way

These were behaviour, not design, but the same files were open.

| Where | Problem |
| --- | --- |
| `lab.css`, heat path | `--heat-ink` did not apply on the non-selectable path, leaving poor text contrast on the dark cells of the `output` step |
| `lab.css`, heat vs row highlight | The heatmap overwrote the row-highlight background and the highlight vanished. Heat cells now show it as a ring |
| `MatrixGrid.tsx` | A blocked cell also got `is-heat`, so `--blocked-bg` never applied (the softmax step with the mask on) |
| `AttentionLab.tsx` | `.formula__sub` had no CSS, so the d in `d_k` never dropped to a subscript |
| `DocLayout.astro` | `.pager__link--prev` had no rule |
| `DocLayout.astro` | `.toc__link--h2` had no rule and rendered unstyled on every document |
| `PathLengthDiagram.astro` | An inline stroke attribute lost to the `.tmap__line` class, so the emphasis on token 1 never showed |
| After renaming tokens | Three SVG components still referenced tokens that no longer existed. A full sweep found and fixed 25 of them |

That last one is a regression the rebuild caused. Renaming a token silently
breaks inline `var()` references outside the CSS. A script that sweeps for
undefined `var()` references caught it, and there are now none.

# Single-page rebuild and a full rewrite of the prose (2026-09-11)

## Why

Two things were raised.

1. **Structure** — the content was split across eight documents and listed as
   fragments in the sidebar. It should be one menu item, one page, divided into
   sections.
2. **The prose** — stop leading with "the paper" and rewrite it as something a
   beginner learns theory from. Use many more examples.

## What changed

### Structure

Routes dropped from **17 to 5**.

| Path | Contents |
| --- | --- |
| `/` | root redirect |
| `/{ko,en}/` | a short landing page |
| `/{ko,en}/attention-is-all-you-need/` | the whole article, twelve sections *(moved to `/{ko,en}/` later on 2026-09-11; see the last section)* |

- The sidebar became the contents of the article. The right-hand TOC and the
  previous/next pager were removed (no test referenced them, so it was safe).
- **Section anchor ids are fixed.** Slugging them from the heading text breaks
  every link whenever a heading is reworded. `src/components/site/Section.astro`
  takes an `id`, and `SECTIONS` in `src/lib/nav.ts` is the single source.
- Scroll position was added. An `IntersectionObserver` marks the section being
  read in the sidebar. Without JavaScript the mark is absent and the links still
  work.
- The six sections not written yet hold **their place only**, marked "not written
  yet" with their stage. They are not links in the sidebar.

### The sections

| # | id | Title | Status |
| --- | --- | --- | --- |
| 1 | `problem` | Turning one sentence into another | written |
| 2 | `big-picture` | The whole picture first | written |
| 3 | `numbers` | Handling many numbers at once | written |

The mathematics is not a separate menu: it is **folded into the flow** as

### The prose

**The frame changed.** What used to open with "what this paper claimed" now opens
with "The animal didn't cross the street because **it** was too tired — what is
'it' here?". The correspondence with the paper was taken off the reader-facing
page and moved to one line at the very end plus the coverage document.

**Duplication that was merged** — found by exploring the text.

| Topic | Before | After |
| --- | --- | --- |
| √d_k and how spread out the scores get | 3 places | once, at the end of `#proportion` |
| Why the mask is added before the softmax | 2 places | once, in `#attention` |
| "values chosen by hand" | 3 places | once, in `#numbers` |
| Transpose | 2 places | once, in `#numbers` |
| `## Next` hand-off paragraphs | 7 places | all removed — one page needs no hand-off |

**A real problem fixed** — the actual numbers of `W_Q`, `W_K` and `W_V` appeared
nowhere in the prose, so a reader could not check `Q = XW_Q` on paper. All three
matrices are now printed in `#numbers`. The example in `#attention` was also made
to import from `examples.ts` (some of it had been hard-coded).

| 언어모델 | 입력과 다음 후보의 관계를 먼저 설명하고, 같은 세 조각으로 문장이 자라는 고리를 보여 줍니다. 시작용 확률표와 뒤에서 계산한 확률을 구분합니다. |

공통 이름은 `src/lib/math/examples.ts`의 `LEARNING_EXAMPLE`에서 쓰며,
입력과 기존 수학 계수·fixture의 숫자는 유지했습니다.
한국어 나는 / 학교에 / 갔다, 영어 I / went / to school은 읽기 쉬운 설명용 조각이며
실제 tokenizer 출력이라는 주장은 하지 않습니다.

- 세 행: (1, 0, 1, 0), (0, 1, 0, 1), (1, 1, 0, 0).
- 앞의 W를 곱한 Y: (2, 0), (0, 2), (1, 1). 뒤에서는 이 같은 변환을 Q 역할에 씁니다.
- 연결 실습은 위치 정보·미래 가리기·두 갈래를 추가하므로 개별 attention의 중간값과
  달라질 수 있습니다. 각 실습의 편집 상태는 독립적이며 처음값으로 비교합니다.
- 마지막 행의 점수 약 (0.288, −0.064, −1.506, 1.282)를 softmax하면
  후보 확률 약 (0.219, 0.154, 0.036, 0.591)입니다. 값은 반올림 전으로 계산합니다.
- 시작용 생성 실습은 별도 예시 표로 세 조각과 끝을 선택하며 전체 확률은
  0.6 × 0.6 × 0.7 × 1 = 0.252입니다.

### 직접 보고 확인한 범위

### 목표: 같은 끝말이 왜 다른 다음 조각으로 이어질까요?

추천 출발 상황은 다음 두 글입니다. 새 사이트에 이미 적용한 예시는 아닙니다.

- A: “비가 내렸다. 나는 가방에서 ___”
- B: “수업이 시작됐다. 나는 가방에서 ___”

끝부분은 같고 앞상황만 다릅니다. 독자가 “우산을 / 책을 / 도시락을” 같은 후보 중
하나를 먼저 골라 보게 하면, 앞상황을 참고할 이유가 생깁니다. 비가 와도 책을 꺼낼 수
있으므로 정답·오답 판정은 하지 않습니다. 서로 다른 가능성에 어느 정도 무게를
주는지 비교하는 과제입니다. 초기 화면에는 이 질문·조작·변화만 보여 주고,
아래의 아홉 장면 설명을 통째로 화면에 옮기지 않습니다.

| 장면 | 이미 아는 것 | 직접 하는 행동과 화면 변화 | 새로 이해할 한 가지 | 아직 몰라도 되는 것 | 다음 질문 |

### 기존 엔진으로 확인한 연결과 남은 데이터 문제

src/lib/math/model.ts의 tinyDecoder는 입력 행렬을 받아 같은 위치·계수·블록·출력 변환을
거쳐 단계별 표현과 어휘 확률을 반환합니다. 새 엔진을 만들 필요가 있는지 보기 위해
기존 함수를 그대로 호출해 첫 행만 바꾸는 작은 계산을 해 봤습니다. 계수를 맞추거나
어휘 이름을 바꾸지 않았습니다.

| 입력 | 마지막 위치의 최종 표현 | 마지막 위치의 후보 확률 |
| --- | --- | --- |
| 기존 X: (1,0,1,0) / (0,1,0,1) / (1,1,0,0) | (0.288, −0.064, −1.506, 1.282) | (0.219, 0.154, 0.036, 0.591) |
| 첫 행만 (0,1,0,1)로 변경; 나머지 두 행 동일 | (0.222, −0.041, −1.492, 1.312) | (0.203, 0.156, 0.037, 0.604) |

마지막 위치의 출발 벡터는 그대로인데 최종 표현과 확률은 달라집니다. 따라서 기존
계산 엔진으로 “앞 문맥 숫자→마지막 표현→어휘 점수/확률”을 추적할 수 있습니다.
그러나 현재 어휘는 나는·학교에·갔다·끝이고 출력 변환은 4×4 단위행렬입니다.
두 경우 모두 끝 후보가 가장 큽니다. 이 계산은 우산/책의 개연성을 학습한 모델이
아니며, A/B 상황을 우산/책 확률로 바꾸는 근거는 아직 마련하지 않았습니다.

우선순위는 같은 입력·출력 데이터와 계산 기록으로 장면 1부터 8까지 추적하는 것입니다.
그렇게 하려면 A/B의 교육용 조각·ID·embedding·출력 어휘와 계수의 출처를 정하고,
같은 계산 결과를 후보 표와 내부 도표에 함께 공급해야 합니다. 원하는 결론에 맞게
계수를 조정한 뒤 학습된 모델처럼 설명하지 않습니다. 현재 벡터의 각 자리에 비·수업
뜻을 임의로 붙이지도 않습니다. 아직 그 데이터 교체·검증을 구현하지 않았습니다.

현재 자료를 먼저 재사용하는 대안은 A/B를 **직관 시연(설명용 확률)**으로 분명히
표시하고, 기존 문장을 **별도 작은 계산 모형(실제로 계산한 값)**으로 전환하는 것입니다.
이때 첫 표의 임의 확률이 뒤의 toy attention 출력인 것처럼 선으로 연결하지 않습니다.
수치가 달라지는 이유와 두 예시의 경계를 화면에 남겨야 합니다. 교육용 토큰화와
실제 토크나이저의 차이, 표시하지 않은 어휘가 있다면 그 확률 몫도 보존합니다.

전치의 기초 도표는 현재 X의 3×4→4×3 재배열을 보여 줍니다. Q/K 모든 쌍 장면에

3×2→2×3 값으로 연결해야 하며, 현재 TransposeFlip을 이미 그렇게 바꿨다고 보고하지
않습니다. 행렬곱은 표현 변환, 비교 점수의 일괄 계산, 참고 비율에 따른 V 가중합에서
각각 어떤 입력과 결과를 갖는지 구분합니다.

시나리오 재구성과 새 도표의 직접 검수가 끝나기 전에 공개 push하지 않습니다.

### 실제 화면을 보고 덜어 낸 조작

Arc의 로컬 페이지에서 이전 단계·후보 고르기·다시 보기·처음부터 만들기 네 버튼과
탭처럼 보이는 네 단계 표시를 실제로 봤습니다. 결과가 물음표라서 그림을 이해하기
전에 조작법을 먼저 찾아야 했습니다. 사용자 지시에 따라 그 조작과 표시를 제거했고,
새 옵션·모드·후보별 버튼·데이터·엔진은 추가하지 않았습니다.

처음부터 “나는 학교에”와 붙인 결과 “나는 학교에 갔다”를 함께 보여 주며,
갔다의 70% 행과 새 조각을 강조합니다. 후보는 클릭 불가 설명 요소입니다.
동작 버튼은 **이 새 입력으로 다음 조각 보기** 하나입니다. 끝에서 같은 버튼이
**처음부터 다시 보기**로 바뀝니다. 초기 화면은 움직이지 않고, 사용자 조작 결과에만
짧은 전환을 사용합니다. 전체 경로의 수학 접기는 끝 표시 이후에 나타납니다.

Arc에서 새로고침 후 위 입력·확률·결과·버튼 한 개를 실제 픽셀로 확인했습니다.
그 버튼을 한 번 눌러 이전 결과 전체가 새 입력 “나는 학교에 갔다”가 되고,
네 후보를 유지한 채 끝 표시 100%, 나머지 0%로 바뀌는 화면과 끝 토큰 강조를 봤습니다.
같은 버튼을 Enter로 실행해 시작→나는 60%로 다시 보는 동작도 직접 확인했습니다.
이때 드러난 한국어 “나는가/나는를” 문구는 조사 선택이 필요 없는 자연스러운 문장틀로
고쳤습니다. 이후 최신 대기 요청에 따라 Arc를 더 조작하지 않았습니다.

현재 직접 증거는 **KO 데스크톱 오프닝의 첫 1회→끝→키보드 다시 시작**입니다.
처음부터 네 회차 전체·반복 클릭·최종 문구·EN·모바일을 Arc에서 끝까지 확인한 것은
아닙니다. W 도표의 직접 before/after도 미검증입니다. 19개 목록의 기존 완료 두 개는
당시 버전의 기록이고, 최신 버전의 완전한 직접 검수 완료로 승격하지 않습니다.

### 검수 지적 보완

- 가려진 **점수**는 −∞, softmax 이후 **비중**은 0.000으로 표시합니다. 실제 maskedScores와 weights를 구분해 읽습니다. 기존 E2E의 잘못된 비중 기대값도 실제 수학에 맞춰 수정했습니다.
- 입력을 바꾸면 단계 설명도 같은 AttentionResult에서 읽습니다. X 첫 칸 1→3일 때 첫 Q는 (4, 0), S는 [[0, 8, 4], [8, 0, 2], [4, 2, 2]], 마지막 출력은 약 (3.528, 0.654)입니다.
- attention 초기에는 읽기용 X와 현재 단계만 보여 줍니다. 입력 편집·설정·단계 점프는 접고, 현재 단계 번호·이름은 계속 보여 줍니다. 좁은 단계 목록을 열면 현재 버튼이 보이도록 가로 위치를 맞춥니다.
- 이어서 해보기는 현재 단계의 행렬을 보여 주며, 어휘 확률은 마지막 단계에서 나타납니다. 위치를 끈 단계 설명도 실제 계산과 맞춥니다.
- 숫자 입력은 공통 NumberInput으로 빈칸·음수 부호·소수 입력 중 상태를 보존합니다. 유한한 숫자만 계산으로 전달합니다. 행렬·내적·softmax·정규화 입력 네 곳에 적용했습니다.
- 두 비중 실습은 p와 1−p로 합 1을 유지합니다. 일반 W 편집은 음수·1보다 큰 값·합이 1이 아닌 계수를 그대로 허용합니다.
- 토큰 선택은 기본 위치 설정의 마지막 행을 사용하는 독립 실습임을 밝힙니다. 난수 u·구간·선택 화살표는 sampling일 때 나타납니다.
- 위치 끝점, 음수 정규화 막대, 손실 주석, FFN 머리말·꼬리말, 잔차 결과식에 여백을 확보했습니다. 손실 초기화 버튼과 가중치 갱신 점의 현재/갱신 뒤 라벨을 추가했습니다.
- decoder의 여섯 층 연결 도식은 입력 세 행 → 출력 세 행을 유지합니다. encoder의 다섯 원문 행과 구분합니다.
- 학습 도식은 입력 [시작, 나는, 학교에, 갔다]와 정답 [나는, 학교에, 갔다, 끝]의 한 칸 이동을 직접 보여 줍니다. 영어도 같은 구조입니다.
